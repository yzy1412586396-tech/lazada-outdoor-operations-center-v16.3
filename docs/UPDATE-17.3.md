# V17.3 四表库存识别初版

2026-10-12，小更新从 V17.2 增加 0.1，安装元数据 17.3.0。重做库存流程，菲律宾与泰国使用相同规则。

## 四张来源表

1. 马帮库存表：SKU、中文名称、实际仓库、可用库存量。自动识别优先选可用库存量，不选仓位库存；升级旧配置时重新识别此列，仓库对应关系保留。
2. 店铺库存表：原始导出模板，读取 SellerSKU、sku.skuId、Status、标题和各仓库库存。
3. 店铺预售表：以 sku.skuId 精确关联 Enable 的 Yes / No，不按行号或 SellerSKU 替代关联。缺失、冲突、无法识别或同 ID 对应 SellerSKU 不一致时保持原样并列异常。
4. 组合明细表：完整组合 SKU 与组件、正整数数量。缺失和冲突不等于已证实缺货。

马帮与组合表按国家共享；店铺库存与预售按国家和店铺分别保存。四表分别上传、覆盖、清除。仓库对应、基础列设置按国家和店铺保存，旧配置作为迁移来源保留。切换国家/店铺后清除旧分析，异步保存、恢复、导出检查所属上下文。

## 确认后的规则

- Yes：单仓自动处理保持原 SellerSKU、仓库和库存；原多仓普通商品按用户确认的例外保留原库存最多的一个仓库，清空其余仓，原SKU和所选原库存数不变。
- No 普通商品：完整 11 位 SKU 查询全部已映射仓库，选可用数量最大的实际仓库。大于 10 件填写数字 9999，其他已识别仓库库存留空。
- 最大可用量小于或等于 10 件：查询其他普通 SKU 的后四位同款，比较各候选的最大单仓库存，候选必须大于 10 且比原 SKU 更充足。替换后保留原 S+数字 后缀。
- 没有有效更优同款：No 普通商品库存全部留空，列入人工处理并标记预售；不自动开启平台预售。
- 替换会造成 SellerSKU 重复：不替换，低库存 No 商品清空库存并列异常及预售，不能为避免碰撞擅自新增后缀。
- 中文候选：在店铺原库存对应的映射仓库内查询，原表没有正库存仓库时使用当前 SKU 最大库存对应仓库；中文名经字符规范化后的编辑相似度至少 95%，且库存大于 10 并更充足。仅展示和导出最多五项供人工确认，不自动替换。
- 组合：所有组件必须在同一个实际马帮仓库同时满足各自数量，不跨仓相加，不换组件 SKU，也不修改组合整行。没有满足条件的共同仓库时列预售；数据不完整时列异常。
- 原店铺普通 No 行多仓有库存，允许按上述确定性结果整理为单仓。原多仓的Yes普通商品、以及因马帮缺失、冲突或原库存仓未映射而保持原样的No普通商品，按确认例外保留店铺原库存最多的仓库，清空其余仓，原SKU不变。组合或其他未知数据保持原样；最终若仍多仓有库存，列异常并拦截正式导出。允许下载标明含待确认行的核对预览。
- 最终有正库存且 Status=Inactive 的商品列未上架；不修改 Status。

## 预览与导出

每页绘制 100 条，分页不改变导出范围。展示 SKU ID、预售状态、原库存、最终库存、判定原因、组合组件和中文候选。人工名单增加马帮仓库数量、同款查询、候选、组件及四个来源文件的版本信息。

正式文件保持原 Sheet、行、列、价格与平台元数据；只修改授权的 SellerSKU 和库存，Status/SellerSKU 规范为文本、有效库存为数字或留空。导出后重新解析成品验证。核对预览保留待确认异常，不能代替已通过最终校验的正式文件。

## 代码与验证入口

`app/inventory-engine-v15.js` 保留历史 API 名称，内部 VERSION 为 17.3；纯规则不依赖 DOM，可独立测试。主要函数为 parseSku、buildMabangIndex、bestAlternative、nameSimilarity、analyze、auditResults。物理仓库键确保同一映射下的不同实际仓库不会合并。

`app/inventory-v15.js` 负责四表解析与持久化、SKU ID 关联、仓库对应、分页和原模板回填；保存旧文件名称和存储槽，避免升级丢失三表缓存。新增 presale 槽及国家/店铺配置键。

测试入口：tests/inventory-v173-unit.cjs、tests/inventory-v173.cjs、tests/inventory-v173-renderer.js。源文件留在本机，通过环境变量提供输入目录，不纳入公开仓库或安装包。
