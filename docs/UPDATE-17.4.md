# V17.4 活动库存保护与清零规则

2026-10-13，小更新从17.3增加0.1。四表读取、SKU ID关联、国家店铺隔离及组合同仓检查保留。

## 执行优先级

1. Status=active按用户业务规则作为活动中处理。原SKU、库存及原行XML保持不动，缺货或非指定仓仍有库存时提示活动中并列人工处理。用户明确确认active保护高于非指定仓清零，程序不擅自清除这些活动行。
2. 未预售、库存不足且指定仓全为0的行视为已处理，跳过SKU替换和重复缺货报备；已经全零的活动行也跳过，原行XML不动。
3. 其他非active未预售普通行保留最大单仓、10件边界及同款查找规则。有货在唯一指定仓写9999，其余仓写数字0；没有更优库存的已证实缺货行全部写0，作为清零完成，不进入缺货人工名单。
4. 非active行非指定仓强制写数字0，不能把未映射仓保留为唯一仓。指定仓多仓时只保留指定仓原数量最多的一个。已开预售指定仓库存保护保留，非指定仓按新规则清零。
5. 已证实未预售组合缺货也清零完成，不换组合SKU；未知或冲突的库存、预售和拆分数据仍列异常，不把数据异常冒充已证实缺货。

原来的未上架标签来自Status=inactive且最终库存>0；本版移除自动未上架标签，避免与活动保护规则混淆。

## 替换SKU唯一性

先尝试替代标准SKU加原后缀。重复时，在标准替代SKU后分配最小未占用的大写S1、S2、S3等。检查范围包括所有原SellerSKU及本次已分配SKU，按原行顺序确定，不叠加成S1S2，不改活动行。无冲突时继续保留原S后缀。

## 预览和导出

新增活动中和已处理/清零完成筛选。已开预售筛选按预售表Yes计数，包含受活动保护的预售商品。正常缺货清零不进入人工名单；中文候选仍可在该结果卡片中查看，缺货清零本身不作为报备。

导出保持active及已处理原行XML，其余只修改授权字段。非指定仓和自动调整行的其他仓写数字0。原行数、价格、隐藏Sheet及平台元数据保持，导出后复核完整工作簿。

测试入口为tests/inventory-v174-unit.cjs和tests/inventory-v174.cjs；V17.3测试入口作为兼容转发保留，历史规则原测试仍在release/v17.3分支。

组合SKU的活动提示和已处理判断先核对组件同仓可用数量，避免因组合编号没有普通库存记录而误判缺货。
