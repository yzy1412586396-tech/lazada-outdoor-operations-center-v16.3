# V18.0：上下架判断、人工二次核对与店铺黑名单

2026-10-14。按大更新主版本加1，显示V18.0，安装元数据18.0.0。V17.8工作中的原生窗口修正合并到本版，未单独发布V17.8安装包。

## 纠正基础含义

Status=active是商品上架；inactive是下架。之前按“活动中”进行保护的库存分支废弃。历史版本公告只描述历史行为，本版规则优先。菲律宾与泰国使用同一套判断实现，各自保存国家和店铺数据。

## 确认后的处理顺序

1. 当前国家、当前店铺黑名单以sku.skuId精确匹配，优先冻结整行，免加工、免异常及待处理。SKU名称或SellerSKU变化不影响ID冻结。特殊SKU跳过规则继续生效。
2. 马帮未匹配、数据冲突、组合定义或组件数据缺失都属于未知，原行保留并提示核对，不能推断为缺货。SKU格式特殊仅列特殊提示。
3. 普通SKU库存>10为有货，<=10为不足。缺货优先同款，之后显式关联SKU；替换保留原S数字后缀，重名分配最小未占用大写S1、S2等。组合仍按同一实际仓库的组件数量判断，不跨仓拼凑。
4. 已上架且原SKU或替换SKU有货：按规则加工SKU、单一指定仓9999、其余仓0。是否预售不再阻止有货替换；Yes增加人工标签“有货需关预售”，不自动修改预售表。
5. 已下架且有货或有可换SKU：强提醒置顶。确认前整行原封不动，包括非指定仓。选择同意上架后才应用建议SKU、指定仓及active；保持下架则整行保留。可重新选择。
6. 确认缺货、未预售且无替换：指定仓原值均为0时保留原上下架状态及指定仓；否则把status改为inactive，指定仓库存原值不变。非指定仓数字0。
7. 缺货且已开预售、无替换：保持原SKU、上下架及指定仓库存，非指定仓0；没有有货候选时不增加“有货需关预售”。
8. 黑名单、待确认下架商品、保持下架商品和未知/特殊冻结行是整行保留例外；其他处理行非指定仓必须为数字0。缺货下架不为了满足旧单仓规则而更改指定仓原值。

## 人工二次核对

表格展示SKU ID、标题、原SKU与最终SKU、预售状态、原上下架与最终上下架、仓库原值及最终值、理由。可修改最终SKU、上下架及指定仓库存，点击“保存本行修改”。库存必须为非负整数、非指定仓0，人工分配不能产生多个有货仓或重复SKU。输入保留焦点，草稿随分页及筛选保留；修改会撤销完成确认。

下架有货逐条选择同意或保持下架后，勾选“已完成二次核对”才能正式导出。尚有未保存草稿时不能导出。完整结果始终保留全部商品，筛选和分页不裁剪导出。导出后重新读取SKU、status、库存值及类型；生成期间上下文或核对内容变化会中止。

右侧×经确认加入黑名单，立即撤销该商品本轮修改并冻结原行。执行库存识别右侧“黑名单库”可按当前国家店铺查看与移出；移出当前店铺名单会清除旧分析，重新识别后生效。黑名单是本地应用数据，使用独立country/store键保存，不加入国家共用仓库模板。

## 体验与窗口

每页最多100条，强提醒排序在分页之前；固定右侧冻结按钮，非指定仓明细折叠。弹窗使用HTML dialog顶层，国家/店铺切换关闭弹窗并使旧分析失效。

保留本轮原生窗口修正：取消Windows透明且禁用缩放的组合，使用不透明、resizable/maximizable/thickFrame及原生最大化还原。Windows10原生外层边界与Mac不同，页面内部保留圆角。没有Windows10实机环境，候选安装包不能宣称Windows原生拖边已验收。
