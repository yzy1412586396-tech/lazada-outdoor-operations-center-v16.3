# V16.3 功能与内容批注

以下依据当前运行的 app.asar 中页面、业务模块和 Electron 代码整理。界面会动态插入部分导航项，所以既参考 app/index.html，也参考 app/inventory-v15.js、app/daily-expense-plugin.js 等文件。此处描述的是程序具备的流程，不代表对用户当前数据库中的每条记录做了核对。

| 模块 | 功能和数据流 | 批注 |
| --- | --- | --- |
| 运营总览 | 汇集店铺、控价库和近期处理信息，并提供活动报名、全店改价入口。 | 供人工检查与跳转；具体结果仍需在各业务模块确认。 |
| 店铺管理 | 按国家、店铺管理商品底库、早鸟价、主推商品等信息。 | 多店铺数据需维持隔离；切换菲律宾和泰国时加载不同的本地数据。 |
| 库存识别 | 导入店铺商品表与马帮库存表，比较 CFS、高易两个仓库，筛出无货、仓库错位、低库存、组合不可售，并提示同款替代 SKU。 | 识别阶段做分析与导出；组合商品的完整组件检查受组合拆解数据限制。SKU 后缀与电池规则属于业务核心，修改前应以实际样本验证。 |
| 控价数据库 | 导入 Excel 并手工指定 SKU、名称和不同控价列；支持普通商品库、泳池库、版本历史、冲突提示、明细搜索、单条修改和删除。 | 同一库中的同 SKU 多价格是冲突；跨普通/泳池库的相同 SKU 不自动算冲突。清空或替换数据前应先导出或备份。 |
| 活动报名 | 将控价、活动门槛、早鸟价、主推商品与库存风险用于报名判断，再回填活动模板。 | 程序说明异常项默认不导出；业务人员仍需复查导出的模板和平台规则。 |
| 全店改价 | 用控价匹配店铺商品并生成价格回填文件。 | 未匹配 SKU 保留原表价格；导出前需核对国家、店铺及价格类型。 |
| 日报汇总 | 汇总日报数据、生成 Excel 结果，并与费用模块联动。 | V16.3 的 AM 列按各店“360/360费用”最终值填入，取手动覆盖或自动识别结果；其它自定义费用不会因金额相同而进入 AM。 |
| 一键日报费用、月度费用 | 上传、识别、编辑并按店铺管理费用，支持批量处理和手动覆盖。 | V16.3 修复了批量处理时重复整页重绘的问题；具体金额应在导出前核对。 |
| 操作记录与更新公告 | 保存处理日志，展示版本说明。 | 操作记录可用于追溯处理过程，但不能替代原始 Excel 或完整审计证据。 |
| 数据设置与备份 | 使用本机 SQLite 保存业务数据，支持本地备份、恢复与下载管理。 | 数据库、备份和下载不随代码上传 GitHub。恢复备份前应确认来源及当前数据。 |
| AI 分析 | 管理模型服务商、加密保存 API Key，并按允许的本地业务上下文构建分析请求。 | 使用外部模型时，请先核对所选上下文；代码上传不包含本机 Key 或 AI 会话。 |
| Northstar 只读接口 | 主进程可启动本机只读 HTTP 接口，向独立 Northstar 项目提供受限数据视图。 | 本仓库只收录 V16.3 应用内接口代码，不包含 lighthouse-ops-platform 独立项目；接口设计为只读，不代表能代替运营人员执行写入。 |

## 代码位置

- app/index.html：主要页面、导航、控价/活动/改价/日报交互及内嵌前端逻辑。
- app/inventory-engine-v15.js、app/inventory-v13.js、app/inventory-v15.js：库存匹配规则与看板。
- app/daily-expense-plugin.js：日报费用流程。
- app/desktop-enhancements.js：桌面交互、下载与界面增强。
- app/ai-observer.js：AI 分析界面。
- electron/main.js、electron/preload.js、electron/ipc-handlers.js：主进程、渲染进程桥接与 IPC。
- electron/database.js、electron/schema.js：本地 SQLite 与数据结构。
- electron/services/credential-store.js：本机凭据保存逻辑；仓库没有实际凭据。
- electron/northstar-server.js：只读接口实现。
