# V17.0 · 三国多控价数据库修复

按照小更新 +0.1 的规则，从 V16.9 顺延到 V17.0（安装元数据 17.0.0）。本次是维护更新。

修复手动列映射导入绕过选择器、写入国家默认库的问题。数据库内普通库与泳池库、控价、冲突、版本、来源和列映射都按目标库保存。历史中无法对应现有库的记录会保存在独立“历史恢复库”，不会静默混入其他库。

菲律宾、泰国、马来西亚分别保存控价、店铺、规则及历史。马来西亚使用 MYR 和用户确认的菲律宾同款 SKU 匹配规则。本次新增的是马来西亚控价、活动报名、全店改价支持，没有新增马来西亚专用日报或库存模板。

## 使用

1. 在顶部选择国家。
2. 在“控价数据库”点“新增数据库”，分别建立本土店、跨境店等控价库并命名。
3. 导入控价表前，在导入区域选择目标库，再确认列映射并导入。普通和泳池控价模块仍各自独立。
4. 活动报名、全店改价都在页面上选择控价数据库。各模块选择会按国家保存，重启后保留。
5. 切换分析库后旧结果清除，需要重新分析；分析或导出过程中切换国家、改变控价时中止过期结果。

旧版已经写入默认库的数据无法推断原本应该属于哪个本土/跨境库。升级保留现有价格，请用原始控价文件重新导入正确的库，不会自动猜测搬移。

## 验证

三国各两个数据库使用同一个 SKU、不同控价完成真实 XLSX 映射导入、活动匹配、冲突、版本恢复、缓存更新和重启持久化测试。原始商品表与组合明细在三国执行早鸟保护开关、匹配、组合计价、导出及模板保留回归。新增数据库上下文快照按库隔离，选择单库不包括其他库的历史控价。

已在 Mac 上检查控价管理、活动报名、全店改价界面，以及 Windows 界面表面路径的大、小窗口截图。Windows 安装包与 Mac 使用同一源代码；仍没有 Windows 10 原生测试环境，Windows 包沿用用户授权的候选试用方式。

覆盖安装前关闭旧版。安装身份与数据目录保持一致，保留原有本机数据。Mac 本地应用已更新。
